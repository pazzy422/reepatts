### What this means

The contract has two functions with textbook reentrancy shapes:

1. **`withdraw(uint256)`** — the highest-severity finding (`SLOAD-CALL-SLOAD-SSTORE`, severity 95). This is the exact shape of the 2016 DAO hack. **Critical risk.**
2. **`transfer(address,uint256)`** — the second pattern (`SLOAD-CALL-SSTORE`, severity 90). If the recipient is a contract, the external call can re-enter `transfer` before the sender's balance has been updated. **High risk.**

A reviewer reading this report would:
1. Verify the SSTORE offsets against a decompiler
2. Check whether the function in question is `nonReentrant`-guarded (reepatts will already down-weight guarded functions, but the reviewer can confirm)
3. Recommend a fix: apply the `nonReentrant` modifier from OpenZeppelin, or restructure to follow the checks-effects-interactions pattern

> Note: this is a sample report. The address used in this example may not produce these findings on the live network — the patterns depend on the bytecode of whichever contract you point reepatts at. Run `bash scripts/scan.sh <address> --network mainnet` to get the real report for a real contract.
